### Look at twice

- **Behaviour change (S07/C2).** Detection now skips dot-directories and `target/`. A repo whose only Python is under `.github/scripts/`, or whose only Dockerfile is in `.devcontainer/`, is no longer detected as Python or Dockerfile. This was approved as part of the design; no snapshot changed.
- **`arch` vs `all` (S06/P3, S07/C1).** Only `nfr-review all` passes the config's `llm` block and `--include-tests` into the arch pipeline. `nfr-review arch` has neither `--config` nor `--include-tests`, so it keeps the defaults.
- **Snapshot handling.** S13 and S02 dropped duplicate graphify `structure-*` lines from their refreshes. S04 then removed all 304 of them, because graphify is off by default. The snapshots would no longer catch graphify being switched back on by accident.
- **Tests that could not fail first.** In S05, `TestWindowsRelativePath` passed immediately, because the PR's own locator fix was already on the branch. The executor showed it catches a regression by temporarily reverting the fix. In S09, the Task 1 commit landed while the dummy-key `unit` run still had the one failure the plan expected; plain `unit` was green, and Task 2 fixed that test.
- **Test-suite isolation (S09).** `tests/conftest.py` now blocks `.env` loading and replaces every `create_llm_client` site for every test. Before this, a dummy key produced 91 real LLM calls from 65 tests.
- **Issue re-keying (S05/W1).** A Windows-keyed issue is adopted only when no issue exists under the new key. If both exist, the old one is left alone and will probably be closed as resolved.
- **Closure boundary (S02/R1).** Blocking calls inside closures that run on the executor (e.g. `.map(|x| std::fs::read(x))` in an async fn) are no longer reported. An `async {}` block in a sync fn is reported as "in async fn `<name>`".
