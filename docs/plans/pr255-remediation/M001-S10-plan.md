## Task 1 — H1: recompile the lockfiles

**Row:** H1. **Files:** `requirements.txt`, `requirements-dev.txt` (modify).
**Consumes:** final `pyproject.toml` (after S03, S04). **Produces:** lockfiles
that include typst, graphviz, graphifyy, networkx, aiohttp and their
transitive deps, hold `tree-sitter` below 0.26, and no longer list `anthropic`
in dev.

Facts established while planning:

- The header of both files says `autogenerated by pip-compile with Python 3.11`.
  `/opt/homebrew/bin/pip-compile` is pip-tools 7.5.3 and its shebang is
  `#!/opt/homebrew/opt/python@3.11/bin/python3.11`, so it resolves markers
  under Python 3.11, the same as the header. Use that binary by absolute path.
- `graphifyy==0.9.97` (core) declares `tree-sitter<0.26,>=0.25` (from
  `.venv/lib/python3.11/site-packages/graphifyy-0.9.97.dist-info/METADATA`).
  Its other caps (`tree-sitter-python<0.26`, `-go<0.26`, `-rust<0.25`,
  `-java<0.25`, `-cpp<0.25`, `-c-sharp<0.25`, `-typescript<0.25`) are already
  met by the current pins; only the `tree-sitter==0.26.0` pin conflicts.
  The fix is `--upgrade-package tree-sitter`, which lets the resolver pick the
  newest `tree-sitter` that satisfies both `>=0.23` (ours) and `<0.26`
  (graphifyy). Do not add a cap to `pyproject.toml`.
- `anthropic` is in the dev lockfile only because the old `[dev]` extra listed
  it; `pyproject.toml` `[dev]` no longer does, so a recompile drops it and its
  transitive-only packages (`distro`, `docstring-parser`, `jiter`, `sniffio`,
  and any of `anyio`/`httpx`/`httpcore`/`h11`/`certifi`/`idna` no longer needed
  by another dependency).
- The `[llm]` extra is not compiled (decision H1 / D1). Neither command passes
  `--extra=llm`. If pip-compile fails while preparing metadata because of the
  `ai-tooling @ file:///${PROJECT_ROOT}/../ai-tooling` URL, stop and record the
  error in the evidence file; do not edit `[llm]`.
- Lockfile consumers: no CI job, pre-commit hook or the license check installs
  from these files. `license-check` runs `pip install -e .` from
  `pyproject.toml`; the Dockerfile builds from `pyproject.toml` and
  `.dockerignore` excludes both lockfiles. Their only CI effect is the
  `requirements*.txt` path filters on the `cve-scan` and `container-e2e` jobs
  in `.github/workflows/ci.yml`, so this change will trigger both jobs on the
  PR. Dependabot's existing `pip` ecosystem entry will now keep these files
  current. No follow-up change is needed for the license check.
- pip-compile resolves for the host platform (macOS arm64). The
  `tree-sitter-dockerfile` line therefore resolves to the 0.2 wheel; whether
  pip-tools carries the S03 marker onto that line is recorded in evidence
  (step 7), not hand-edited, because a hand edit breaks the no-diff rerun.

## Task 2 — H4: patch zlib1g, drop the ignores, pin the base image

**Row:** H4. **Files:** `Dockerfile`, `.trivyignore`,
`.github/dependabot.yml` (modify). **Consumes:** the Debian security fix
`1:1.3.dfsg+really1.3.1-1+deb13u1` named in the current `.trivyignore`
comment. **Produces:** a runtime image whose zlib1g is at or above that
version, no zlib entries in `.trivyignore`, both `FROM` lines pinned to the
multi-arch index digest of `python:3.14-slim`, and a Dependabot `docker`
ecosystem that moves the digest.

Decision (ledger: "the plan decides it"; M001-decisions S10): pin by digest
and add Dependabot `docker`. The explicit zlib1g upgrade stays even with the
pin, because a pinned base no longer picks up Debian fixes on rebuild.

Steps:

1. **Failing check.**

   ```bash
   bash -c 'set -e
   ! grep -q -E "CVE-2026-76844|CVE-2026-85091|zlib1g" .trivyignore
   grep -q "^       zlib1g" Dockerfile
   test "$(grep -c -E "^FROM python:3\.14-slim@sha256:[0-9a-f]{64}( AS builder)?$" Dockerfile)" = 2
   grep -q "package-ecosystem: \"docker\"" .github/dependabot.yml' && echo H4-STATIC-OK
   ```

   Expected now: non-zero exit, no `H4-STATIC-OK`.

2. **Baseline the CVEs on the current image** (records whether today's base
   still carries them). Build with the `container-e2e` token's build half,
   then scan with Trivy. `trivy` is not installed on the host, so run it in a
   container against a saved image archive:

   ```bash
   podman build --platform linux/amd64 -t nfr-review:e2e-test .
   mkdir -p /private/tmp/nfr-review-s10-trivy
   podman save -o /private/tmp/nfr-review-s10-trivy/image.tar nfr-review:e2e-test
   podman run --rm -v /private/tmp/nfr-review-s10-trivy:/scan docker.io/aquasec/trivy:latest \
     image --input /scan/image.tar --scanners vuln --format json \
     --cache-dir /scan/cache --output /scan/before.json
   grep -o -E 'CVE-2026-(76844|85091)' /private/tmp/nfr-review-s10-trivy/before.json | sort -u
   ```

   Record the output (either CVE IDs or nothing) for evidence.

3. **Change `Dockerfile` runtime stage.** In the existing runtime `RUN
   apt-get update …` block, add `zlib1g` to the package list and extend the
   comment above it. `apt-get install` upgrades an already-installed package
   that is named on the command line, which is why it is listed rather than
   using `--only-upgrade` (that flag would stop `fonts-liberation` and `git`
   from being installed). The block becomes:

   ```dockerfile
   # fonts-liberation provides Liberation Sans used by typst; git is needed for repo analysis.
   # zlib1g is named so apt upgrades the base image's copy to the Debian
   # security fix for CVE-2026-76844 and CVE-2026-85091.
   RUN apt-get update \
       && apt-get install -y --no-install-recommends \
          fonts-liberation \
          git \
          zlib1g \
       && rm -rf /var/lib/apt/lists/*
   ```

4. **Pin both `FROM` lines by the multi-arch index digest.** Obtain the digest
   of the OCI image index (not a per-architecture manifest) from Docker Hub;
   the `Accept` headers request the index, and the `content-type` line
   confirms it:

   ```bash
   TOKEN=$(curl -fsS "https://auth.docker.io/token?service=registry.docker.io&scope=repository:library/python:pull" | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')
   curl -fsSI -H "Authorization: Bearer $TOKEN" \
     -H "Accept: application/vnd.oci.image.index.v1+json" \
     -H "Accept: application/vnd.docker.distribution.manifest.list.v2+json" \
     https://registry-1.docker.io/v2/library/python/manifests/3.14-slim \
     | tee /private/tmp/nfr-review-s10-trivy/digest-headers.txt
   DIGEST=$(awk 'tolower($1)=="docker-content-digest:"{print $2}' /private/tmp/nfr-review-s10-trivy/digest-headers.txt | tr -d '\r')
   grep -i '^content-type: application/vnd.oci.image.index.v1+json\|^content-type: application/vnd.docker.distribution.manifest.list.v2+json' /private/tmp/nfr-review-s10-trivy/digest-headers.txt
   echo "$DIGEST" | grep -E '^sha256:[0-9a-f]{64}$'
   ```

   Cross-check that it is an index containing `linux/amd64`:
   `podman manifest inspect "docker.io/library/python@$DIGEST" | grep -c '"architecture": "amd64"'`
   prints at least 1. Then write it into both lines:

   ```bash
   sed -i '' -E "s#^FROM python:3\.14-slim( AS builder)?\$#FROM python:3.14-slim@${DIGEST}\1#" Dockerfile
   grep -n '^FROM ' Dockerfile
   ```

   Expected: `FROM python:3.14-slim@sha256:… AS builder` and
   `FROM python:3.14-slim@sha256:…` with the same digest. Record the digest in
   evidence.

5. **`.trivyignore`.** Delete the three zlib lines and the blank line before
   them (the comment `# zlib1g — OS-layer CVEs in python:3.14-slim base image.`,
   the comment `# Fixed in 1:1.3.dfsg+really1.3.1-1+deb13u1; will clear on next base-image rebuild.`,
   `CVE-2026-76844`, `CVE-2026-85091`). The file then ends with
   `CVE-2026-42504` and a newline, exactly as on main:
   `git diff --exit-code main -- .trivyignore && echo trivyignore-matches-main`.

6. **`.github/dependabot.yml`.** Append a third entry in the existing style:

   ```yaml

     - package-ecosystem: "docker"
       directory: "/"
       schedule:
         interval: "weekly"
       groups:
         docker-minor:
           update-types:
             - "minor"
             - "patch"
   ```

7. **Static check passes.** Rerun the step 1 command; expected
   `H4-STATIC-OK`.

8. **`container-e2e` passes** (expand the token exactly, see Validation 3).

9. **zlib1g version in the built image:**

   ```bash
   podman run --rm --platform linux/amd64 --entrypoint sh nfr-review:e2e-test -c \
     'v=$(dpkg-query -W -f="\${Version}" zlib1g); echo "$v"; dpkg --compare-versions "$v" ge "1:1.3.dfsg+really1.3.1-1+deb13u1" && echo zlib-fixed'
   ```

   Expected: the installed version, then `zlib-fixed`.

10. **Trivy scan reports neither CVE**, both as CI runs it (severity filter,
    `ignore-unfixed`, the repo `.trivyignore`) and unfiltered:

    ```bash
    rm -f /private/tmp/nfr-review-s10-trivy/image.tar
    podman save -o /private/tmp/nfr-review-s10-trivy/image.tar nfr-review:e2e-test
    cp .trivyignore /private/tmp/nfr-review-s10-trivy/.trivyignore
    podman run --rm -v /private/tmp/nfr-review-s10-trivy:/scan docker.io/aquasec/trivy:latest \
      image --input /scan/image.tar --scanners vuln --severity CRITICAL,HIGH \
    ```

## Task 3 — H5: CI hygiene

**Row:** H5. **Files:** `.github/workflows/ci.yml` (modify). **Consumes:**
`git show main:.github/workflows/ci.yml` (the deleted step and comment).
**Produces:** test-core with its "Test summary" step back, the cve-scan
comment back, and test-llm measuring coverage and uploading
`coverage-report-llm`.

Decision (M001-decisions, H5): test-llm uploads its coverage as its own
artifact rather than being combined with test-core's; the jobs run on
separate runners and a combine step would need a new job. The DoD's "merged
into the report" is met in that sense: the LLM-only modules' coverage is
measured and published next to `coverage-report-core`.

Facts established while planning:

- `[tool.coverage.report]` in `pyproject.toml` sets `fail_under = 88`, and
  pytest-cov applies the coverage config's `fail_under` when
  `--cov-fail-under` is not given. test-llm runs six test files, so `--cov`
  alone would fail that job on the threshold. test-llm therefore passes
  `--cov-fail-under=0`; the 88% gate stays on test-core (`coverage report
  --fail-under=88`). Step 4 demonstrates this locally.
- `actionlint` (`/opt/homebrew/bin/actionlint`) is installed; it is not part of
  the pre-commit config (only `check-yaml` covers workflows). On the current
  file it exits 1 solely on shellcheck SC2086/SC2129 notes in the ci-complete
  "Summary" step, which also exist on main (16 shellcheck notes on main's file).
  The restored "Test summary" step has the same style. The check below
  therefore runs `actionlint -ignore 'SC2086' -ignore 'SC2129'`, which exits 0
  on the current file.

Steps:

1. **Failing check.**

   ```bash
   bash -c 'set -e
   grep -q "^      - name: Test summary$" .github/workflows/ci.yml
   grep -q "# Vulnerabilities only: secret scanning of the image flags example" .github/workflows/ci.yml
   grep -q -- "--cov --cov-append --cov-fail-under=0" .github/workflows/ci.yml
   grep -q "name: coverage-report-llm" .github/workflows/ci.yml
   ! git diff main -- .github/workflows/ci.yml | grep -q -E "^-.*(Test summary|Test Results \(Python|Vulnerabilities only|credentials in third-party|Our own source is covered)"' && echo H5-OK
   ```

   Expected now: non-zero exit, no `H5-OK`.

2. **Restore "Test summary"** as the last step of the `test-core` job,
   directly after the "Update coverage badge" step (its position on main),
   copied verbatim from `git show main:.github/workflows/ci.yml`:

   ```yaml

         - name: Test summary
           if: always()
           run: |
             echo "## Test Results (Python ${{ matrix.python-version }})" >> $GITHUB_STEP_SUMMARY
   ```

   ```bash
   rm -f coverage-llm.xml .coverage
   ```

   Expected: `exit=1` with a "Required test coverage of 88% not reached"
   line (record it). Then change the test-llm "Run LLM integration tests"
   step and add the upload step after it:

   ```yaml

           run: |
             pytest -n auto -m "not regression" \

               --cov-report=term-missing --cov-report=xml:coverage-llm.xml \
               tests/test_llm_client.py \
               tests/test_llm_config.py \

           uses: actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9 # v7.0.2
   ```

   Keep whatever test-file list the job has at execution time if an earlier

5. **The new command passes locally and writes the report:**
